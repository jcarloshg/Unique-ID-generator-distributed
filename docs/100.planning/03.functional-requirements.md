### 3.2 — Error Codes

| Code | HTTP Status | Description | Retry? |
|------|-------------|-------------|--------|
| INTERNAL_ERROR | 500 | Unexpected generator error | No |
| CLOCK_BACKWARDS | 500 | System clock went backwards | No |
| SEQUENCE_OVERFLOW | 500 | Too many requests in 1ms | No |
| GENERATORS_UNAVAILABLE | 503 | All instances down | Yes |
| REQUEST_TIMEOUT | 504 | Request exceeded timeout | Yes |

### 3.3 — Error Response Format

```json
{
  "error": "Human-readable message",
  "code": "MACHINE_READABLE_CODE",
  "details": "Optional additional info",
  "retry_after_ms": 1000
}
```

### 3.4 — Error Handling Flows

**Flow 1: Single Generator Failure**
```
Client → nginx → Generator 1 (DOWN)
                    ↓
              Generator 2 or 3 (healthy)
                    ↓
              Return ID to client
```

**Flow 2: All Generators Down**
```
Client → nginx → No healthy upstream
                    ↓
              Return 503 { "code": "GENERATORS_UNAVAILABLE" }
```

**Flow 3: Clock Going Backwards**
```
Generator detects: current_time < last_time
                    ↓
              Log ERROR with timestamps
              Return 500 { "code": "CLOCK_BACKWARDS" }
              Alert ops team
```

**Flow 4: Sequence Overflow**
```
Generator detects: sequence >= 4096
                    ↓
              Wait until millisecond advances
              Reset sequence = 0
              Generate ID
```

## Step 4 — Concurrent Request Handling

### 4.1 — Concurrency Requirements

**Owner:** Tech Lead
**Sprint:** Planning Sprint 1
**Timebox:** 3 hours

**Requirements from Q3.1:**
> Support concurrent requests without collisions

**Concurrency Analysis:**

| Metric | Value |
|--------|-------|
| Target RPS | 10,000 |
| Peak RPS | 15,000 |
| Per-generator capacity | 4,096,000/second |
| Concurrent connections per generator | 100-1000 |

### 4.2 — Thread Safety Design

**Single-Generator Concurrency:**

```python
class IdGenerator:
    def __init__(self, datacenter_id, machine_id):
        self.datacenter_id = datacenter_id
        self.machine_id = machine_id
        self.sequence = 0
        self.last_timestamp_ms = 0
        self._lock = threading.Lock()  # Or asyncio.Lock
    
    def generate_id(self) -> int:
        with self._lock:  # Critical section
            current_ms = get_current_timestamp_ms()
            
            if current_ms == self.last_timestamp_ms:
                self.sequence += 1
                if self.sequence >= 4096:
                    # Wait for next millisecond
                    while current_ms == self.last_timestamp_ms:
                        current_ms = get_current_timestamp_ms()
                    self.sequence = 0
            
            if current_ms < self.last_timestamp_ms:
                raise ClockBackwardsError()
            
            self.last_timestamp_ms = current_ms
            
            return build_snowflake_id(
                timestamp=current_ms,
                datacenter=self.datacenter_id,
                machine=self.machine_id,
                sequence=self.sequence
            )
```

### 4.3 — Multi-Generator Collision Prevention

**Design:** Each generator has unique (datacenter_id, machine_id) tuple.

| Instance | Datacenter ID | Machine ID |
|----------|---------------|------------|
| Generator 1 | 1 | 1 |
| Generator 2 | 1 | 2 |
| Generator 3 | 1 | 3 |

**Collision Prevention:**
- Datacenter ID × Machine ID must be unique across all instances
- Timestamp + Sequence ensures uniqueness within a machine
- Different machines have different timestamps at any given moment

### 4.4 — Test Scenarios for Concurrency

| Scenario | Test Method | Expected Result |
|----------|-------------|-----------------|
| 1000 concurrent requests to 1 generator | Load test | All 1000 IDs unique |
| 1000 concurrent requests to 3 generators | Load test | All 1000 IDs unique |
| Burst of 4097 requests in 1ms | Load test | 4096 succeed, 1 waits for next ms |
| 10K RPS sustained for 1 minute | Load test | No errors, all IDs unique |

## Step 5 — Time Ordering Specification

### 5.1 — Ordering Requirements

**Requirement from Q3.1:**
> Time-based ordering within a single generator

**Ordering Guarantees:**

| Scope | Guarantee | Mechanism |
|-------|-----------|-----------|
| Within single generator | Monotonically increasing | Sequence number per ms |
| Across generators | Not guaranteed | Clock drift possible |
| Within single millisecond | Unique via sequence | 12-bit counter |

### 5.2 — Timestamp Component

**Epoch:** 1288834974657 (Nov 04, 2010, 01:42:54.657 UTC)

**Timestamp Validation:**
- Must be >= epoch
- Must be monotonically increasing (per machine)

**Time Range:**
- Start: Nov 04, 2010
- End: ~2082 (69.7 years from epoch)

### 5.3 — ID Parsing for Ordering

```python
def parse_timestamp(id: int) -> datetime:
    """Extract timestamp from Snowflake ID."""
    timestamp_ms = (id >> 22) + EPOCH
    return datetime.fromtimestamp(timestamp_ms / 1000, tz=UTC)

def parse_sequence(id: int) -> int:
    """Extract sequence number from Snowflake ID."""
    return id & 0xFFF

def parse_machine(id: int) -> int:
    """Extract machine ID from Snowflake ID."""
    return (id >> 12) & 0x1F

def parse_datacenter(id: int) -> int:
    """Extract datacenter ID from Snowflake ID."""
    return (id >> 17) & 0x1F
```

### 5.4 — Sortability Tests

| Test | Description | Expected Result |

| T1 | Generate 1000 IDs on single generator | Sorted by timestamp, then by sequence |
| T2 | Generate IDs with 1ms delay between batches | Timestamp increases with batches |
| T3 | Parse 1000 IDs and sort by extracted timestamp | Sorted order matches ID order |

## Step 6 — PostgreSQL Persistence Design

### 6.1 — Persistence Requirements

**Requirement from Q3.1:**
> Persist generated IDs to PostgreSQL (optional/auditing)

**Design Decisions:**

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Enabled by default | Yes | Audit compliance |
| Blocking vs Async | Async | Don't block ID generation |
| Schema | Single table | Simple, sufficient |
| Connection pooling | Yes | Handle 10K RPS |

### 6.2 — Database Schema

```sql
CREATE TABLE generated_ids (
    id BIGINT PRIMARY KEY,
    timestamp_ms BIGINT NOT NULL,
    datacenter_id SMALLINT NOT NULL,
    machine_id SMALLINT NOT NULL,
    sequence_num SMALLINT NOT NULL,
    generated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    metadata JSONB
);

-- Indexes for common queries
CREATE INDEX idx_generated_ids_timestamp ON generated_ids(timestamp_ms DESC);
CREATE INDEX idx_generated_ids_datacenter_machine ON generated_ids(datacenter_id, machine_id);
CREATE INDEX idx_generated_ids_generated_at ON generated_ids(generated_at DESC);
```

### 6.3 — Async Write Design

```python
class AsyncIdRepository:
    def __init__(self, pool: asyncpg.Pool):
        self.pool = pool
        self._queue: asyncio.Queue = Queue(maxsize=10000)
        self._worker_task = None
    
    async def persist_id(self, id: int, timestamp_ms: int, 
                         datacenter_id: int, machine_id: int, 
                         sequence: int, metadata: dict = None):
        # Non-blocking enqueue
        await self._queue.put({
            'id': id,
            'timestamp_ms': timestamp_ms,
            'datacenter_id': datacenter_id,
            'machine_id': machine_id,
            'sequence_num': sequence,
            'metadata': metadata
        })
    
    async def _worker(self):
        batch = []
        while True:
            try:
                # Batch up to 100 items or wait 10ms
                item = await asyncio.wait_for(
                    self._queue.get(), 
                    timeout=0.01
                )
                batch.append(item)
                
                if len(batch) >= 100:
                    await self._flush_batch(batch)
                    batch = []
            except asyncio.TimeoutError:
                if batch:
                    await self._flush_batch(batch)
                    batch = []
    
    async def _flush_batch(self, batch: list):
        async with self.pool.acquire() as conn:
            await conn.executemany("""
                INSERT INTO generated_ids 
                (id, timestamp_ms, datacenter_id, machine_id, sequence_num, metadata)
                VALUES ($1, $2, $3, $4, $5, $6)
                ON CONFLICT (id) DO NOTHING
            """, [(item['id'], item['timestamp_ms'], 
                   item['datacenter_id'], item['machine_id'],
                   item['sequence_num'], item['metadata']) for item in batch])
```

### 6.4 — Graceful Degradation

| PostgreSQL State | Behavior |
|-----------------|----------|
| Available | Async writes enabled |
| Unavailable | Continue generating IDs, skip writes, log warning |
| Recovered | Resume writes automatically |

### 6.5 — Test Scenarios

| Test | Description | Expected Result |
|------|-------------|-----------------|
| T1 | Generate 1000 IDs | All 1000 persisted to DB |
| T2 | PostgreSQL down, generate 100 IDs | All 100 returned to client, none persisted |
| T3 | PostgreSQL recovers | Writes resume automatically |
| T4 | Duplicate ID attempted | ON CONFLICT DO NOTHING |
