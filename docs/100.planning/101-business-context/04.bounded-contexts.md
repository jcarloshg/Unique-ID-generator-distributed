# Bounded Contexts

## Overview
This document defines the four bounded contexts in the Unique ID Generator Distributed system, their responsibilities, entities, and relationships.

## Context Definitions

### Context 1: ID Generation

| Attribute | Value |
|-----------|-------|
| **Name** | ID Generation Context |
| **Responsibility** | Generate unique, time-ordered 64-bit IDs using the Snowflake algorithm |
| **Technology** | Python (FastAPI/Flask) |
| **Owned Entities** | Generator, SnowflakeId, GeneratorConfig |
| **External Dependencies** | None (core domain) |
| **Boundaries** | Pure domain; no external dependencies |

**Entities:**

| Entity | Description | Attributes |
|--------|-------------|------------|
| Generator | Service instance that generates IDs | datacenter_id, machine_id, sequence, last_timestamp |
| SnowflakeId | Value object representing a 64-bit ID | id, timestamp_ms, datacenter_id, machine_id, sequence |
| GeneratorConfig | Configuration for a generator instance | datacenter_id, machine_id, epoch |

**Ports (Interfaces):**
- `IClock` — Provides current timestamp
- `IIdPersistence` — Persists generated IDs (implemented by Persistence Context)

---

### Context 2: Persistence

| Attribute | Value |
|-----------|-------|
| **Name** | Persistence Context |
| **Responsibility** | Store generated IDs for auditing and traceability |
| **Technology** | PostgreSQL |
| **Owned Entities** | GeneratedIdRecord, AuditLog |
| **External Dependencies** | PostgreSQL database |
| **Boundaries** | Receives writes from ID Generation Context |

**Entities:**

| Entity | Description | Attributes |
|--------|-------------|------------|
| GeneratedIdRecord | Database record of a generated ID | id (PK), timestamp_ms, datacenter_id, machine_id, sequence_num, generated_at, metadata |
| AuditLog | Audit trail entry | id, action, timestamp, details |

**Public Interface:**
- `INSERT INTO generated_ids (...) VALUES (...)`
- `SELECT * FROM generated_ids WHERE datacenter_id = ? AND machine_id = ?`

---

### Context 3: Load Balancing

| Attribute | Value |
|-----------|-------|
| **Name** | Load Balancing Context |
| **Responsibility** | Distribute incoming HTTP requests across healthy generator instances |
| **Technology** | nginx |
| **Owned Entities** | Upstream, RoutingRule |
| **External Dependencies** | Generator instances (health checks) |
| **Boundaries** | Entry point for all client requests |

**Entities:**

| Entity | Description | Attributes |
|--------|-------------|------------|
| Upstream | Collection of backend generators | server list, health status |
| RoutingRule | Load balancing algorithm | algorithm (round-robin/least-conn) |

**Configuration:**
```nginx
upstream generators {
    least_conn;
    server generator-1:5001;
    server generator-2:5002;
    server generator-3:5003;
}
```

---

### Context 4: Monitoring

| Attribute | Value |
|-----------|-------|
| **Name** | Monitoring Context |
| **Responsibility** | Display health status and metrics for all generator instances |
| **Technology** | Vite + React |
| **Owned Entities** | HealthStatus, Metrics, DashboardView |
| **External Dependencies** | Generator instances (polling /health) |
| **Boundaries** | Read-only; no writes to other contexts |

**Entities:**

| Entity | Description | Attributes |
|--------|-------------|------------|
| HealthStatus | Current health of an instance | instance_id, status, uptime_seconds, ids_generated |
| Metrics | Aggregated system metrics | total_ids, requests_per_second, error_rate |
| DashboardView | UI component displaying system status | instances[], system_total, healthy_count |

## Shared Kernel

The following concepts are shared across multiple contexts:

| Concept | Shared Between | Ownership | Definition |
|---------|---------------|-----------|------------|
| Datacenter ID | ID Generation, Load Balancing, Monitoring | ID Generation | 5-bit identifier (0-31) |
| Machine ID | ID Generation, Load Balancing, Monitoring | ID Generation | 5-bit identifier (0-31) |
| Instance ID | ID Generation, Monitoring | ID Generation | String format: dc-{XX}-machine-{YY} |
| Timestamp | ID Generation, Persistence | ID Generation | Milliseconds since epoch |

**Principle:** Datacenter ID and Machine ID are **owned** by ID Generation Context. Other contexts consume these values through the API.

---

## Context Relationships

| From | To | Relationship | Description |
|------|----|--------------|-------------|
| Client | Load Balancing | Consumer | Client requests IDs |
| Load Balancing | ID Generation | Calls | Routes requests to generators |
| ID Generation | Persistence | Depends On (optional) | Persists IDs to PostgreSQL |
| Monitoring | ID Generation | Polls | Reads /health endpoint |
| Load Balancing | Monitoring | None | Independent |

---

## Anti-Patterns Check

| Anti-Pattern | Found? | Mitigation |
|--------------|--------|------------|
| Same entity means different things in different contexts | No | Each context has clear ownership |
| God object (one context does everything) | No | Clear separation of concerns |
| Shared database between contexts | No | PostgreSQL owned by Persistence Context only |
