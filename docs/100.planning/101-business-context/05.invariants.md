# Business Invariants

## Overview
This document defines the business rules and invariants that must always hold true across all bounded contexts. These are enforced by design and/or runtime checks.

## Invariant Categories

1. **ID Generation Invariants** — Rules for the Snowflake algorithm
2. **Persistence Invariants** — Rules for database writes
3. **Load Balancing Invariants** — Rules for request routing
4. **Monitoring Invariants** — Rules for health reporting

---

## ID Generation Invariants

### I-001: Zero Collision Guarantee

| Attribute | Value |
|-----------|-------|
| **Rule** | An ID must never collide with any other ID generated across all generator instances |
| **Enforcement** | Algorithm guarantees: (datacenter_id, machine_id, timestamp, sequence) tuple is unique |
| **Proof** | Max combinations = 32 DCs × 32 machines × 4,096 sequences/ms × 1,000 ms/s = 4.19 billion IDs/second |
| **Runtime Check** | None required (mathematically impossible to collide) |

**Implementation Constraint:**
```python
# Each generator MUST have unique (datacenter_id, machine_id) tuple
assert (datacenter_id, machine_id) not in use_by_other_generators
```

### I-002: Monotonic Ordering Per Machine

| Attribute | Value |
|-----------|-------|
| **Rule** | IDs generated on the same machine must be monotonically increasing |
| **Enforcement** | Sequence number increments within same millisecond |
| **Edge Case** | Sequence resets to 0 on new millisecond; IDs remain strictly increasing |

**Implementation:**
```python
def generate_id():
    current_ms = get_current_timestamp_ms()
    if current_ms == last_timestamp_ms:
        sequence += 1
    else:
        sequence = 0
        last_timestamp_ms = current_ms
    return build_id(timestamp=current_ms, sequence=sequence)
```

### I-003: Sequence Reset

| Attribute | Value |
|-----------|-------|
| **Rule** | Sequence number must reset to 0 at the start of each millisecond |
| **Enforcement** | Clock abstraction provides millisecond boundary |
| **Validation** | Unit test verifies sequence == 0 after timestamp change |

### I-004: Clock Monotonicity

| Attribute | Value |
|-----------|-------|
| **Rule** | Timestamp must never go backwards |
| **Enforcement** | Runtime check; if detected, return HTTP 500 and alert ops |
| **Tolerance** | Clock drift < 1ms: Warning logged. Clock drift 1-10ms: Degraded mode. Clock drift > 10ms: Fatal error. |

**Implementation:**
```python
def validate_timestamp(current_ms: int, last_ms: int) -> None:
    if current_ms < last_ms:
        drift = last_ms - current_ms
        if drift > 10:
            raise ClockBackwardsError(f"Clock went backwards by {drift}ms")
        elif drift > 1:
            logger.warning(f"Clock drift detected: {drift}ms")
```

### I-005: Sequence Overflow Prevention

| Attribute | Value |
|-----------|-------|
| **Rule** | Maximum 4096 IDs per millisecond per machine (sequence 0-4095) |
| **Enforcement** | If sequence would exceed 4095, wait for next millisecond |
| **User Impact** | None (transparent wait) |

**Implementation:**
```python
def generate_id():
    current_ms = get_current_timestamp_ms()
    if current_ms == last_timestamp_ms:
        if sequence >= 4095:
            # Wait for next millisecond
            while current_ms == last_timestamp_ms:
                current_ms = get_current_timestamp_ms()
            sequence = 0
        else:
            sequence += 1
    else:
        sequence = 0
        last_timestamp_ms = current_ms
```

### I-006: Bit Field Constraints

| Field | Bits | Range | Constraint |
|-------|------|-------|------------|
| Sign | 1 | 0 | Always 0 |
| Timestamp | 41 | 0 to 2^41-1 | ms since epoch |
| Datacenter ID | 5 | 0-31 | Must fit in 5 bits |
| Machine ID | 5 | 0-31 | Must fit in 5 bits |
| Sequence | 12 | 0-4095 | Must fit in 12 bits |

## Persistence Invariants

### I-010: ID Primary Key

| Attribute | Value |
|-----------|-------|
| **Rule** | Generated ID is the primary key in the database |
| **Enforcement** | PostgreSQL UNIQUE constraint |
| **Conflict Handling** | INSERT ... ON CONFLICT DO NOTHING (idempotent) |

### I-011: Async Write Non-Blocking

| Attribute | Value |
|-----------|-------|
| **Rule** | Database writes must never block ID generation |
| **Enforcement** | Async queue with separate worker thread |
| **Fallback** | If DB unavailable, IDs continue to be generated (graceful degradation) |

### I-012: Write Order

| Attribute | Value |
|-----------|-------|
| **Rule** | IDs may be written to database out of order |
| **Enforcement** | None (eventual consistency acceptable for auditing) |
| **Note** | Timestamp in ID itself provides global ordering |

## Load Balancing Invariants

### I-020: Request Distribution

| Attribute | Value |
|-----------|-------|
| **Rule** | Requests must be distributed across healthy generator instances |
| **Algorithm** | least_conn (connects to least busy generator) |
| **Fallback** | If all generators unhealthy, return 503 |

### I-021: Health Check Interval

| Attribute | Value |
|-----------|-------|
| **Rule** | Unhealthy generators must be removed from pool within 5 seconds |
| **Enforcement** | nginx health check interval = 5s |
| **Check** | GET /health on each generator |

### I-022: Timeout Propagation

| Attribute | Value |
|-----------|-------|
| **Rule** | Client timeout (5s) must be respected |
| **Enforcement** | nginx proxy_read_timeout = 10s (> client timeout) |

## Monitoring Invariants

### I-030: Health Status Accuracy

| Attribute | Value |
|-----------|-------|
| **Rule** | Dashboard must show accurate health status within 10 seconds of change |
| **Polling Interval** | GET /health every 5 seconds |
| **Max Staleness** | 5 seconds (polling interval) |

### I-031: ID Counter Accuracy

| Attribute | Value |
|-----------|-------|
| **Rule** | ID counter displayed must be >= actual IDs generated |
| **Tolerance** | eventual consistency acceptable (async writes) |
| **Source of Truth** | Generator instance counter (not database) |

### I-032: Instance ID Format

| Attribute | Value |
|-----------|-------|
| **Rule** | Instance ID must follow format: dc-{XX}-machine-{YY} |
| **Example** | dc-01-machine-03 |
| **Validation** | Regex: `^dc-[0-9]{2}-machine-[0-9]{2}$` |

## Anti-Pattern Rejection

### Anemic Domain Model — REJECTED

| Anti-Pattern | Decision | Rationale |
|--------------|----------|----------|
| Business logic in database triggers | Rejected | Business logic lives in Generator service |
| Business logic in UI | Rejected | All computation in domain layer |
| Getters/setters without behavior | Rejected | IdGeneratorService has actual methods |

### Gold-Plating — REJECTED

| Anti-Pattern | Decision | Rationale |
|--------------|----------|----------|
| Multi-region active/active | Rejected | Single datacenter in v1 |
| Database sharding | Rejected | Single PostgreSQL instance sufficient |
| Distributed consensus (Raft/Paxos) | Rejected | Not needed; Snowflake handles uniqueness |

### Resume-Driven Development — REJECTED

| Anti-Pattern | Decision | Rationale |
|--------------|----------|----------|
| Choosing exotic technology | Rejected | Python chosen (team skill) |
| Kubernetes for 3 instances | Rejected | Docker Compose sufficient |
| GraphQL for simple API | Rejected | REST/HTTP is adequate |

## Invariant Violation Handling

| Violation | Severity | Action | Recovery |
|-----------|----------|--------|----------|
| ID Collision detected | CRITICAL | Alert immediately, stop service | Manual investigation |
| Clock backwards > 10ms | CRITICAL | Stop generating, alert ops | Restart service |
| Sequence overflow not handled | HIGH | Fix code | Redeploy |
| Database write blocks | HIGH | Alert, bypass persistence | Continue without DB |
| Health check wrong | MEDIUM | Fix dashboard | Refresh |
