# Availability Analysis

## Overview
This document analyzes the availability requirements and designs for the Unique ID Generator service, including redundancy strategies and gap analysis.

## Availability Target

**Target:** 99.9% uptime (3 nines)

### Allowed Downtime by Period

| Period | Total Minutes | 99.9% Allowed Downtime | 99.99% Allowed Downtime |
|--------|---------------|------------------------|------------------------|
| Per day | 1,440 | 1.44 minutes | 8.64 seconds |
| Per week | 10,080 | 10.08 minutes | 60.48 seconds |
| Per month | 43,830 | 43.83 minutes | 4.38 minutes |
| Per year | 525,600 | 8.76 hours | 52.56 minutes |

### Error Budget Formula

```
Error Budget = (1 - Availability Target) × Total Minutes
Monthly Error Budget = 0.001 × 43,830 = 43.83 minutes
```

### Individual Component Availability

| Component | Design | Estimated Availability |
|-----------|--------|------------------------|
| nginx | Single instance | 99.5% |
| Generator 1 | Single instance | 99.5% |
| Generator 2 | Single instance | 99.5% |
| Generator 3 | Single instance | 99.5% |
| PostgreSQL | Single instance | 99.5% |
| Vite Dashboard | Stateless | 99.9% |

### System Availability Calculation

**Assuming independent failures:**

```
Generator Subsystem (any 1 of 3 must work):
P(generator_up) = 0.995
P(at least one up) = 1 - (1 - 0.995)³ = 1 - 0.000125 = 99.9875%

System = nginx × Generator Subsystem × PostgreSQL × Dashboard
System ≈ 0.995 × 0.999875 × 0.995 × 0.999
System ≈ 98.99%
```

## Redundancy Design

### Component Redundancy

| Component | Instances | Redundancy Strategy |
|-----------|-----------|-------------------|
| nginx | 1 | None (SPOF - acceptable for internal) |
| Generator | 3 | N+2 (1 can fail, 2 remain) |
| PostgreSQL | 1 | None (no HA) |
| Dashboard | 1 | None (stateless, can scale) |

### Generator Redundancy

```
With 3 generators:
- 1 failure: 66.7% capacity (acceptable)
- 2 failures: 33.3% capacity (critical)
- 3 failures: 0% capacity (total outage)
```

## nginx Availability

### Single Point of Failure

**Risk:** nginx is a single point of failure for the entire system.

**Mitigation:**
- Internal service only (lower SLA expectations)
- Quick restart capability (< 1 minute)
- Corporate network reliability

**Future Improvement:**
- Keepalived for nginx HA
- AWS ALB if migrating to cloud

---

## PostgreSQL Availability

### Single Instance Risk

**Risk:** PostgreSQL failure causes data loss for audit trail.

| Failure Mode | Impact | Recovery |
|-------------|--------|----------|
| PostgreSQL down | No persistence (IDs still generated) | Restart or restore |
| Disk failure | Data loss | Restore from backup |
| Corruption | Data loss | Restore from backup |

### Mitigation

- Async writes (non-blocking) - IDs still generated without DB
- Daily backups with 7-day retention
- WAL archiving for point-in-time recovery
- Graceful degradation when unavailable

## Availability Improvement Strategies

| Strategy | Availability Gain | Effort | Cost | Priority |
|----------|-------------------|--------|------|----------|
| Add nginx HA (keepalived) | +0.4% | Medium | Low | Future |
| PostgreSQL HA (Patroni) | +0.4% | High | Medium | Future |
| Generator autoscaling | +0.1% | High | High | Future |
| Accept current design | 0 | None | None | v1 |

**Decision for v1:** Accept current design (~99% availability) due to:
- Internal service with lower SLA expectations
- PostgreSQL persistence is optional (graceful degradation)
- 3-generator redundancy covers critical path

## Health Checks

### Generator Health Check

```nginx
upstream generators {
    server generator-1:5001;
    server generator-2:5002;
    server generator-3:5003;
}

# Passive health check
server {
    location / {
        proxy_pass http://generators;
        proxy_connect_timeout 5s;
        proxy_next_upstream error timeout;
        proxy_next_upstream_tries 3;
    }
}
```

### Health Endpoint Response Codes

| State | HTTP Code | Response |
|-------|-----------|----------|
| OK | 200 | `{"status": "ok", ...}` |
| DEGRADED | 200 | `{"status": "degraded", ...}` |
| DOWN | 503 | `{"status": "down", ...}` |
