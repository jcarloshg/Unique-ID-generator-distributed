# Consistency Design

## Overview
This document specifies the CAP trade-off decision, consistency guarantees, and clock synchronization requirements for the Unique ID Generator service.

## CAP Trade-off Decision

### Decision: CP (Consistency over Availability)

| Option | Description | Chosen |
|--------|-------------|--------|
| CP (Consistency) | IDs never collide; service unavailable if partition | ✓ **CHOSEN** |
| AP (Availability) | IDs may have rare collisions; always available | ✗ Rejected |

### Rationale

1. **ID collision is unacceptable** — Creates data integrity issues downstream
2. **Service unavailability is acceptable** — Clients can retry; IDs are not lost
3. **Zero tolerance for silent data corruption** — Cannot have duplicate IDs

### CAP Theorem Context

```
In the presence of a network partition:
- CP systems may become unavailable
- AP systems may return stale/wrong data

For ID generation:
- Wrong data (duplicate ID) = permanent data corruption
- Unavailable = temporary, clients retry
```

## Consistency Guarantees

### Per-Generator Guarantees

| Guarantee | Mechanism | Implementation |
|-----------|-----------|----------------|
| Uniqueness | Algorithm guarantees | (datacenter_id, machine_id, timestamp, sequence) tuple |
| Monotonicity | Sequence number | Increments within same millisecond |
| No collisions | Unique (DC, Machine) tuple | Configuration validation |

### Cross-Generator Guarantees

| Scenario | Outcome | Handling |
|----------|---------|----------|
| Clock drift < 1ms | Safe | Allowed, minor out-of-order possible |
| Clock drift 1-10ms | Warning | Log warning, continue |
| Clock drift > 10ms | Error | Return 500, alert ops |
| Network partition | Degrade | 503 returned, generators continue locally |

## Clock Synchronization

### NTP Requirements

| Requirement | Value | Notes |
|-------------|-------|-------|
| Max drift | ±10ms | Triggers warning at ±1ms |
| Drift check interval | 1 second | Internal validation |
| NTP query interval | 60 seconds | System NTP daemon |
| Acceptable NTP sources | 3+ | For drift detection |

### Clock Validation

```python
class ClockValidator:
    def __init__(self):
        self._last_time_ms = 0
        self._drift_count = 0
        self._max_drift_ms = 0

    def validate(self, current_time_ms: int) -> Tuple[bool, str, int]:
        if current_time_ms < self._last_time_ms:
            drift = self._last_time_ms - current_time_ms
            self._drift_count += 1
            self._max_drift_ms = max(self._max_drift_ms, drift)

            if drift > 10:
                return False, "CRITICAL", drift
            elif drift > 1:
                return False, "WARNING", drift
            else:
                return False, "INFO", drift

        self._last_time_ms = current_time_ms
        return True, "OK", 0
```

### Drift Thresholds

| Drift | Severity | Action |
|-------|----------|--------|
| < 1ms | OK | Accept |
| 1-10ms | WARNING | Log warning, continue generating |
| > 10ms | CRITICAL | Stop generation, alert ops, return 500 |

## Collision Prevention

### Mathematical Proof

**Claim:** With proper configuration, ID collisions are mathematically impossible.

**Proof:**
```
Let G = set of generators
Each g ∈ G has unique (datacenter_id, machine_id) tuple

ID(g, t, s) = (t << 22) | (datacenter_id << 17) | (machine_id << 12) | s

Where:
- t = timestamp_ms (unique per generator)
- s = sequence 0-4095 (unique per t per generator)

For collisions to occur:
∃ g₁, g₂, t₁, t₂, s₁, s₂: ID(g₁, t₁, s₁) = ID(g₂, t₂, s₂)

This requires:
(t₁ << 22) | (dc₁ << 17) | (m₁ << 12) | s₁ = (t₂ << 22) | (dc₂ << 17) | (m₂ << 12) | s₂

Which implies dc₁ = dc₂ AND m₁ = m₂ AND t₁ = t₂ AND s₁ = s₂

Since (dc, m) tuples are unique by configuration,
and (t, s) tuples are unique by sequence management,
collisions are impossible.
```

### Configuration Enforcement

```python
# Each generator MUST have unique (datacenter_id, machine_id)
VALID_PAIRS = [
    (1, 1),  # Generator 1
    (1, 2),  # Generator 2
    (1, 3),  # Generator 3
]

def validate_config(datacenter_id: int, machine_id: int) -> bool:
    return (datacenter_id, machine_id) in VALID_PAIRS
```

## Conflict Resolution

### Collision Scenarios

| Scenario | Probability | Mitigation |
|----------|-------------|------------|
| Same (DC, Machine, Timestamp, Sequence) | 0 (atomic) | Not possible |
| Different machines same ms + sequence | 0 (different machine bits) | Not possible |
| Timestamp overflow race | 0 (single-threaded) | Not possible |

**Conclusion:** Collisions are mathematically impossible given proper configuration.

## Consistency Modes

### Mode 1: Strong Consistency (Default)

All generators must have synchronized clocks within 10ms.

```python
# Enabled by default
STRONG_CONSISTENCY = True
MAX_CLOCK_DRIFT_MS = 10
```

### Mode 2: Eventual Consistency (Not Used)

Allow generators with larger clock drift.

```python
# NOT recommended for ID generation
```

## Implementation

### Generator Consistency Check

```python
import asyncio
import time

class ConsistentIdGenerator:
    def __init__(self, datacenter_id: int, machine_id: int):
        self.datacenter_id = datacenter_id
        self.machine_id = machine_id
        self.sequence = 0
        self.last_timestamp_ms = 0
        self._lock = asyncio.Lock()

    async def generate_id(self) -> int:
        async with self._lock:
            current_ms = int(time.time() * 1000)

            # Clock backwards check
            if current_ms < self.last_timestamp_ms:
                drift = self.last_timestamp_ms - current_ms
                if drift > 10:
                    raise ClockBackwardsError(
                        f"Clock backwards by {drift}ms (CRITICAL)"
                    )
                else:
                    logger.warning(f"Clock drift: {drift}ms")

            # Same millisecond handling
            if current_ms == self.last_timestamp_ms:
                self.sequence += 1
                if self.sequence >= 4096:
                    # Wait for next millisecond
                    while current_ms == self.last_timestamp_ms:
                        current_ms = int(time.time() * 1000)
                        await asyncio.sleep(0.001)
                    self.sequence = 0
            else:
                self.sequence = 0

            self.last_timestamp_ms = current_ms

            return self._build_id(current_ms, self.sequence)
```
