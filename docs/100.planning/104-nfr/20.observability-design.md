# Observability Design

## Overview
This document defines the observability strategy including metrics, tracing, logging, and alerting for the Unique ID Generator service.

## Metrics

### Required Metrics

| Metric | Type | Description | Alert Threshold |
|--------|------|-------------|-----------------|
| ids_generated_total | Counter | Total IDs generated | None |
| request_duration_seconds | Histogram | Request latency | P99 > 50ms |
| error_total | Counter | Total errors | Rate > 1% |
| generator_status | Gauge | 0=down, 1=degraded, 2=ok | Any 0 |
| sequence_current | Gauge | Current sequence | > 4000 |

### Prometheus Format

```python
from prometheus_client import Counter, Histogram, Gauge

ids_generated_total = Counter(
    'ids_generated_total',
    'Total IDs generated',
    ['datacenter_id', 'machine_id']
)

request_duration_seconds = Histogram(
    'request_duration_seconds',
    'Request latency in seconds',
    buckets=[0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0]
)

generator_status = Gauge(
    'generator_status',
    'Generator health status (0=down, 1=degraded, 2=ok)',
    ['instance']
)

sequence_current = Gauge(
    'generator_sequence_current',
    'Current sequence number',
    ['datacenter_id', 'machine_id']
)
```

### Metrics Endpoint

**GET /metrics** returns Prometheus-formatted metrics:


## Tracing

### Correlation ID

Every request should include a correlation ID for distributed tracing.

```python
@app.middleware
async def add_correlation_id(request, call_next):
    correlation_id = request.headers.get('x-correlation-id', str(uuid4()))
    request.state.correlation_id = correlation_id

    response = await call_next(request)
    response.headers['x-correlation-id'] = correlation_id

    return response
```

### Trace Fields

| Field | Description |
|-------|-------------|
| correlation_id | Unique request identifier |
| instance_id | Datacenter-machine identifier |
| timestamp | ISO-8601 timestamp |

## Logging

### Structured Logging

All logs should be in JSON format for machine parsing.

```python
import logging
import json

class JSONFormatter(logging.Formatter):
    def format(self, record):
        log_data = {
            'timestamp': datetime.utcnow().isoformat(),
            'level': record.levelname,
            'correlation_id': getattr(record, 'correlation_id', 'N/A'),
            'instance_id': getattr(record, 'instance_id', 'N/A'),
            'message': record.getMessage(),
        }
        return json.dumps(log_data)

logger = logging.getLogger()
logger.setLevel(logging.INFO)
handler = logging.StreamHandler()
handler.setFormatter(JSONFormatter())
logger.addHandler(handler)
```

### Log Levels

| Level | Usage |
|-------|-------|
| DEBUG | Detailed debugging information |
| INFO | Normal operation (ID generated, etc.) |
| WARNING | Degraded operation (clock drift, etc.) |
| ERROR | Error occurred but handled |
| CRITICAL | Unrecoverable error (clock backwards) |

## Alerting

### Alert Rules

| Alert | Condition | Severity | Action |
|-------|-----------|----------|--------|
| GeneratorDown | status == 0 | WARNING | Log |
| TwoGeneratorsDown | 2+ generators down | CRITICAL | Page ops |
| AllGeneratorsDown | All generators down | CRITICAL | Page ops immediately |
| HighLatency | P99 > 50ms | WARNING | Investigate |
| ErrorRateHigh | error_rate > 1% | WARNING | Investigate |
| ClockDrift | drift > 10ms | CRITICAL | Page ops |
| SequenceNearOverflow | sequence > 4000 | WARNING | Monitor |
| PostgreSQLError | DB error rate > 1% | WARNING | Log |

### Alert Examples

```yaml
# Prometheus alerting rules
groups:
  - name: id_generator
    rules:
      - alert: GeneratorDown
        expr: generator_status == 0
        for: 30s
        labels:
          severity: warning
        annotations:
          summary: "Generator {{ $labels.instance }} is down"

      - alert: AllGeneratorsDown
        expr: sum(generator_status) == 0
        for: 10s
        labels:
          severity: critical
        annotations:
          summary: "All generators are down"

      - alert: HighLatency
        expr: histogram_quantile(0.99, request_duration_seconds) > 0.05
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "P99 latency exceeds 50ms"
```

## SLOs

### Service Level Objectives

| SLO | Target | Error Budget |
|-----|--------|--------------|
| Availability | 99.9% | 43.83 min/month |
| Latency P99 | < 50ms | 1% of requests |
| Throughput | > 10,000 RPS | N/A |
| Error Rate | < 0.1% | 1% of requests |

### Error Budget Tracking

```
Monthly Error Budget = 43.83 minutes
Consumed Error Budget = Sum of downtime minutes
Remaining Budget = Monthly Budget - Consumed

If Remaining Budget < 10%:
  - Pause non-critical deployments
  - Focus on reliability
```
