# Security Design

## Overview
This document defines the security boundaries, data classification, network security, and secrets management for the Unique ID Generator service.

## Security Classification

### Data Classification

| Data Type | Classification | Handling |
|-----------|---------------|----------|
| Generated IDs | Public | No restrictions |
| Internal instance IDs | Internal | Don't expose to external |
| PostgreSQL data | Internal | Network isolation |
| Configuration secrets | Confidential | Environment variables only |
| Logs | Internal | No PII, no secrets |

### PII Assessment

| Item | PII? | Notes |
|------|------|-------|
| Generated IDs | No | Random numbers, no personal data |
| Instance IDs | No | Internal identifiers |
| Timestamps | No | Technical metadata |
| PostgreSQL records | No | Technical audit data |
| Client requests | No | Internal service calls |

**Conclusion:** No PII involved in ID generation.

## Firewall Rules

### Recommended iptables Rules

```bash
# Allow nginx port 80 from internal network (10.0.0.0/8)
iptables -A INPUT -p tcp --dport 80 -s 10.0.0.0/8 -j ACCEPT

# Block generator ports from external
iptables -A INPUT -p tcp --dport 5001:5003 -j DROP

# Block PostgreSQL from external
iptables -A INPUT -p tcp --dport 5432 -j DROP

# Block dashboard from external
iptables -A INPUT -p tcp --dport 3000 -s 10.0.0.0/8 -j ACCEPT
iptables -A INPUT -p tcp --dport 3000 -j DROP
```

## Authentication & Authorization

### Decision

**No authentication required for ID generation endpoint** (per Q4.4)

### Rationale

- Internal service behind corporate network
- IDs are not sensitive data
- Authentication adds latency (conflicts with 10K RPS target)
- Client services are trusted internal services

### Future Considerations

| Scenario | Authentication |
|----------|---------------|
| External exposure | API key or mTLS |
| Multi-tenant | Tenant isolation + API keys |
| Public API | OAuth 2.0 / API keys |

## Secrets Management

### Secrets Required

| Secret | Purpose | Storage |
|--------|---------|---------|
| PostgreSQL password | Database auth | Environment variable |
| Datacenter ID | ID generation | Environment variable |
| Machine ID | ID generation | Environment variable |

### Environment Variables

```bash
# .env file (NOT committed to git)
POSTGRES_PASSWORD=secure_password_here
DATACENTER_ID=1
MACHINE_ID=1
```

### Secrets NOT Required

- No JWT tokens
- No OAuth credentials
- No external API keys
- No TLS certificates (internal only)

## Logging Security

### Logging Rules

1. **Never log generated IDs in full** (privacy)
2. **Never log PII**
3. **Never log secrets or tokens**
4. **Always include correlation ID**

### Safe Log Format

```python
# Good
logger.info(f"Generated ID from {datacenter_id}-{machine_id}", extra={
    'correlation_id': correlation_id,
    'sequence': sequence,
    'timestamp_ms': timestamp_ms
})

# Bad
logger.info(f"Generated ID: {full_id}")  # Don't log full ID
```

### Log Fields

| Field | Required | Description |
|-------|----------|-------------|
| timestamp | Yes | ISO-8601 format |
| level | Yes | DEBUG, INFO, WARNING, ERROR |
| correlation_id | Yes | Request tracing |
| instance_id | Yes | Datacenter-machine identifier |
| message | Yes | Human-readable message |

## Security Headers

### nginx Security Headers

```nginx
server {
    # Remove nginx version
    server_tokens off;

    # Security headers (for dashboard)
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
```

## Container Security

### Dockerfile Security Best Practices

```dockerfile
# Use minimal base image
FROM python:3.11-slim

# Create non-root user
RUN useradd --create-home --shell /bin/bash appuser

# Copy files as appuser
COPY --chown=appuser:appuser . /home/appuser

# Switch to non-root user
USER appuser

# No secrets in image
ENV POSTGRES_PASSWORD=""

# Expose only required ports
EXPOSE 5001
```
