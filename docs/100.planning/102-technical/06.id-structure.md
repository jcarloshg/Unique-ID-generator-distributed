# ID Structure Specification

## Overview

The Unique ID Generator uses a Snowflake-inspired 64-bit ID structure optimized for distributed systems.

## Bit Layout

```
┌────────────┬────────────────────┬───────────────┬─────────────┬──────────────┐
│  Sign Bit  │    Timestamp       │  Datacenter   │   Machine   │   Sequence   │
│    (1)     │      (41)          │     (5)       │    (5)      │    (12)      │
├────────────┼────────────────────┼───────────────┼─────────────┼──────────────┤
│     0      │  ms since epoch    │   0-31        │   0-31      │   0-4095     │
└────────────┴────────────────────┴───────────────┴─────────────┴──────────────┘
            41 bits                5 bits         5 bits       12 bits
```

## Field Definitions

### Sign Bit (1 bit)
- **Value:** Always 0
- **Purpose:** Reserved for future use (e.g., signed/unsigned distinction)
- **Constraint:** Must never be set to 1

### Timestamp (41 bits)
- **Value Range:** 0 to 2,199,023,255,551 (2^41 - 1)
- **Unit:** Milliseconds since epoch
- **Epoch:** 1288834974657 (November 4, 2010, 01:42:54.657 UTC — Twitter Snowflake epoch)
- **Time Range:** 69.7 years from epoch
- **Implication:** IDs will overflow in approximately 2082 (2010 + 69.7 years)

### Datacenter ID (5 bits)
- **Value Range:** 0 to 31
- **Max Datacenters:** 32
- **Assignment:** Static configuration per deployment
- **Constraint:** Must be unique within the system

### Machine ID (5 bits)
- **Value Range:** 0 to 31
- **Max Machines per Datacenter:** 32
- **Assignment:** Static configuration per instance
- **Constraint:** Must be unique within a datacenter

### Sequence Number (12 bits)
- **Value Range:** 0 to 4095
- **Max IDs per Millisecond per Machine:** 4,096
- **Reset:** Every millisecond (per machine)
- **Purpose:** Ensures uniqueness when multiple IDs are generated in the same millisecond

## Mathematical Validation

### Maximum ID Value
```
Max ID = (2^64 - 1) = 18,446,744,073,709,551,615
```

### Maximum Timestamp
```
Max Timestamp = 2^41 - 1 = 2,199,023,255,551 ms
Max Time from Epoch = 2,199,023,255,551 / 1000 / 60 / 60 / 24 / 365.25 ≈ 69.7 years
```

### Capacity Per Machine
```
IDs per millisecond = 2^12 = 4,096
IDs per second = 4,096 × 1,000 = 4,096,000
IDs per minute = 4,096,000 × 60 = 245,760,000
```

### Capacity Per Datacenter (32 machines)
```
IDs per second = 4,096,000 × 32 = 131,072,000
```

### Total System Capacity (32 datacenters)
```
IDs per second = 131,072,000 × 32 = 4,194,304,000
```

## ID Generation Algorithm

```python
def generate_id(datacenter_id: int, machine_id: int, sequence: int, timestamp_ms: int) -> int:
    """
    Generate a 64-bit unique ID.
    
    Args:
        datacenter_id: 5-bit value (0-31)
        machine_id: 5-bit value (0-31)
        sequence: 12-bit value (0-4095)
        timestamp_ms: Milliseconds since epoch
    
    Returns:
        64-bit unique ID
    """
    # Shift and OR each component into position
    id = (timestamp_ms << 22)          # 41 bits for timestamp
    id |= (datacenter_id << 17)       # 5 bits for datacenter
    id |= (machine_id << 12)          # 5 bits for machine
    id |= sequence                     # 12 bits for sequence
    
    return id
```

## ID Parsing (Decoding)

```python
def parse_id(id: int) -> dict:
    """Parse a 64-bit ID into its components."""
    sequence = id & 0xFFF                           # Last 12 bits
    machine_id = (id >> 12) & 0x1F                  # Next 5 bits
    datacenter_id = (id >> 17) & 0x1F              # Next 5 bits
    timestamp_ms = (id >> 22) & 0x1FFFFFFFFFF       # Next 41 bits
    
    return {
        'id': id,
        'timestamp_ms': timestamp_ms,
        'datacenter_id': datacenter_id,
        'machine_id': machine_id,
        'sequence': sequence
    }
```

## Sorting and Ordering

### Time Ordering
IDs are sortable by timestamp component. However, global sortability (across machines) is not guaranteed because:
1. Machine clocks may drift
2. Two IDs generated at the same millisecond on different machines may have different timestamps

### Per-Machine Ordering
Within a single machine, IDs are guaranteed to be monotonically increasing within a millisecond (due to sequence number).

## Overflow Handling

### Sequence Overflow
When `sequence > 4095` (more than 4096 requests in 1ms), the generator must wait until the next millisecond before generating another ID.

```python
if sequence >= 4096:
    # Wait for next millisecond
    while current_timestamp_ms == last_timestamp_ms:
        current_timestamp_ms = get_current_timestamp_ms()
    sequence = 0
```

### Timestamp Overflow
The 41-bit timestamp will overflow around year 2082. Mitigation strategies:
- Change epoch to a future date
- Implement 128-bit IDs (future)
- Plan migration to new ID scheme before 2082

## Validation Rules

1. **Sign bit must be 0** — IDs are unsigned 64-bit integers
2. **Timestamp must be >= epoch** — No IDs with timestamps before epoch
3. **Datacenter ID must be 0-31** — Enforced by 5-bit constraint
4. **Machine ID must be 0-31** — Enforced by 5-bit constraint
5. **Sequence must be 0-4095** — Enforced by 12-bit constraint
6. **ID must be >= 0** — Unsigned integer
