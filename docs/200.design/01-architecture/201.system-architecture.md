# Phase 201 — System Architecture

## Overview
This document provides the complete system architecture for the Unique ID Generator Distributed service, including component interactions, data flows, and deployment topology.

## Architecture Summary

**Pattern:** Hexagonal (Ports & Adapters)
**Deployment:** Docker Compose (single-node)
**Scaling:** Horizontal (add more generators)

## Data Flows

### Flow 1: Generate ID (Happy Path)

```
1. Client → nginx:80 → GET /generate
2. nginx → Generator-1:5001 (least_conn)
3. Generator-1: Generate Snowflake ID
4. Generator-1 → nginx: Response {id: 1825478541164436481}
5. nginx → Client: Response {id: 1825478541164436481}
6. (async) Generator-1 → PostgreSQL: INSERT id
```

### Flow 2: Health Check

```
1. Dashboard → nginx:80 → GET /health
2. nginx → Generator-1:5001: GET /health
3. nginx → Generator-2:5001: GET /health
4. nginx → Generator-3:5001: GET /health
5. nginx → Dashboard: Aggregated health status
```

### Flow 3: Generator Failure

```
1. Client → nginx:80 → GET /generate
2. nginx → Generator-2:5001 (DOWN - removed from pool)
3. nginx → Generator-1:5001 (healthy)
4. Generator-1 → Client: Response {id: ...}
```
